# File outline

给智能体一张**文件地图**，而不是更快的搜索。

## 它解决什么

智能体面对大文件时，瓶颈不是读取速度，而是**缺少坐标系**：`read` 只能从某个位置往后读一段，"该从哪读"这个判断它自己给不出来；`grep` 要求先有关键词，而你刚打开一个 14 MB 的文件时，并没有词可搜。

本插件在模型决定投入 token 读正文之前，先给出位置信息：文件分几个主题、每个主题在哪几行、下一步该读哪一段。

不是搜索加速——实测 ripgrep 扫 14 MB 只要 48 ms，搜索早就够快。

## 三个工具

三件套是一条链，不是三个独立功能：

| 工具 | 回答的问题 | 不返回什么 |
|---|---|---|
| `file_card` | 这是什么文件？多大？有结构吗？ | 不返回正文（只有截断的首尾样本） |
| `outline` | 分几个主题？某个词落在哪几节？整体集中在哪几万行？ | 不返回命中行原文 |
| `digest` | 那一段说什么？还剩多少？ | 不返回整段（超预算就停） |

## 什么时候用

| 文件大小 | 建议 |
|---|---|
| < 10 KB | 直接用内置 `read`。本插件在这里是净负担 |
| 10 KB – 1 MB | 结构不清楚时先 `outline` |
| 1 – 10 MB | 先 `outline`，再 `digest` 取段 |
| > 10 MB | 不要通读。`outline` 定位，`digest` 按段取 |

只在**有结构**的文件上有价值。对无空行、无标题、无重复前缀的超大文本，能给的只有行数和编码——这是定位的边界，不是缺陷。

## 典型流程

```
file_card(path="big.md")          → 14.2 MB / 165,359 行 / 5,276 标题 / 超大文件
outline(path="big.md", keyword="配色")
                                  → 命中 322 节 807 行；最密的是「1. 用户明确请求」
digest(path="big.md", lines="119953-120000", budget=800)
                                  → 返回 24 行 744 token；还剩 224 行，从 119977 继续
```

三次调用替代了原本需要 83 次 `read` 的遍历。

## 硬性保证

| 保证 | 做法 |
|---|---|
| 零 LLM 调用 | 纯确定性字符串处理 |
| 流式 | 内存占用与文件大小无关；100 MB 与 1 MB 同价 |
| 确定性 | 无时间戳进入输出（`file_card` 的 mtime 除外，那是文件属性） |
| 只读 | 不写、不删、不改任何文件 |
| 工作区受限 | 路径必须落在 Session 工作目录内，越界直接拒绝 |
| 零运行时依赖 | 只用 Node 内置模块 |
| 输出上限 8000 字符 | 超出时截断并写明原长度 |

## token 口径

DSH 核心用 `字符数 / 4`（`CHARS_PER_TOKEN = 4`）。本插件取两者较大值：

```
tokens = max(chars / 4,  CJK字符数 × 0.6 + ASCII字符数 × 0.25)
```

纯英文/代码文件与 DSH 完全一致；中文文件比 DSH 进度条更保守（实测差 1.2–1.7 倍）。理由：`budget` 的目的是防止上下文被撑爆，宁可低估容量。

## 支持的文件类型

**解析**：Markdown（ATX 标题）、纯文本、日志、CSV、JSON、YAML、JS/TS/Python/HTML/CSS 等任何文本格式。

**编码**：UTF-8、UTF-8 BOM、UTF-16LE、UTF-16BE、GBK/GB18030、Big5。GBK 与 Big5 靠解码结果合理性判别（常用汉字加分，生僻字/假名/西里尔扣分）。

**拒绝并给出替代读取器**：PDF、Word/Excel/PowerPoint（zip 容器）、zip、PNG/JPEG/GIF、ELF、MP4、RIFF 等二进制格式，靠魔数识别。

## 平台

**仅 Windows。** 代码不含平台分支（路径走 `node:path`，换行兼容 LF/CRLF/CR），但只在 Windows 11 + DSH 0.2.2-rc.3 上实测过。`package.json` 声明 `"os": ["win32"]`，在 macOS 与 Linux 上安装会被包管理器拒绝，而不是装上一个未经验证的版本。

## 已知限制

- 只识别 Markdown ATX 标题。setext 标题、HTML 块、缩进代码块内的内容不参与解析。
- 编码检测只看前 64 KiB；混合编码文件可能判错。
- 极端短的 Big5/GBK 样本仍可能判错（判别信号来自字符分布，样本太短就没信号）。
- 无魔数且无 NUL 字节的自定义二进制会被当作文本。
- 段落降级的高频前缀只统计前 12 个字符，数字归一化为 `#`。

## 安装

在 DSH 中通过 Plugin Manager 安装，或使用 `plugin_manager` 的 `install_bundle` 指向本目录。

安装后需**完全退出 DSH 再重新打开**：Host 侧插件不热加载（刷新页面不够）。
